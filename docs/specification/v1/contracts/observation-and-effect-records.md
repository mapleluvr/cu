# Observation, Archive, and Effect Records Contract

## Status and Scope

This contract defines the exact v1 durable records for captures, current coordinate
authority, archive transactions, history, quotas, and unresolved input effects. It
refines the architecture overview and the Action and Evidence Contract.
It does not add a public command, helper protocol, native-input capability, or a
claim about application-level task success.

All mutations described here occur while the existing exclusive per-run lock is held.
A malformed, incompatible, unconfined, replacement-uncertain, or inconsistent record
fails closed. It is never silently repaired, promoted to action authority, or deleted.

## Common Admission Rules

Every JSON control record in this contract is UTF-8 without a BOM, at most 65,536
bytes, one exact JSON object, at most 64 layers deep, and has no duplicate member
names at any depth. Objects use the exact own-key sets stated here. Timestamps are
canonical UTC RFC3339 milliseconds, matching
`YYYY-MM-DDTHH:mm:ss.sssZ`. SHA-256 values are lowercase 64-hex strings.

`runId` and `workspaceFingerprint` must match the already admitted `cu.run/v1`
record and current workspace. An observation ID is generated by `cu`, is never
client-selected, and matches `^obs_[a-f0-9]{32}$`. An archive transaction ID matches
`^txn_[a-f0-9]{32}$`; an effect ID matches `^eff_[a-f0-9]{32}$`; and a history event
ID matches `^hist_[a-f0-9]{32}_[1-9][0-9]{0,3}$`.

All paths below are derived from admitted IDs and fixed names. No record stores or
accepts a helper path, action-file path, process ID, window handle, target identity,
or raw typed text.

## Run Layout and Confinement

The contractual logical records remain under `<workspace>/.cu/<runId>/`:

```text
run.json
live-observation.json
effect-journal.json
history.ndjson
archive-transaction.json
captures/
  <observationId>.png
  <observationId>.json
@archive/
  <transactionId>/
    staging/
    trash/
```

`@archive` is an internal namespace, cannot be a run ID, and is never exposed in a
receipt. It and every transaction directory must be a confined, non-link directory.
`captures` contains only regular, non-link PNG/sidecar pairs derived from valid
observation IDs. `staging` and `trash` are transaction-private and cannot provide
history or coordinate authority.

Control records use the established bounded stable regular-file protocol. PNG reads
use the same confinement and stable identity/snapshot discipline with an explicit
64 MiB binary ceiling. Archive installation uses temporary private staging, full
validation, fsync, and create-once publication. Live, journal, and transaction state
changes use existing-target-only validated atomic replacement: the caller holds the
run lock; the private staged capability binds the exact target path and exact ordered
direct-ancestor chain; replacement revalidates both the staged candidate and a stable
witness for the current target immediately before cutover, validates the installed
sibling after cutover, and fails closed on uncertainty. It does not claim power-loss durability on Node/Windows;
unknown interruption state requires lock-held recovery proof. A later implementation
must prove these claims with crash, junction, replacement, and concurrent-command
tests.

## Immutable Capture Bundle

A capture bundle is exactly the pair:

```text
captures/<observationId>.png
captures/<observationId>.json
```

The PNG is validated independently before publication: PNG media type, image digest,
byte length, width, and height must agree with its sidecar. The encoded PNG is at
most 67,108,864 bytes (64 MiB); each dimension is an integer in `1..32768`. A rejected
or oversized helper result is never published and leaves the prior live observation
unchanged.

The sidecar has exactly this root shape:

```json
{
  "kind": "cu.capture/v1",
  "schemaVersion": 1,
  "runId": "work-a",
  "workspaceFingerprint": "64-lowercase-hex",
  "observationId": "obs_0123456789abcdef0123456789abcdef",
  "capturedAt": "2026-07-24T00:00:00.000Z",
  "expiresAt": "2026-07-24T00:05:00.000Z",
  "coordinateSpace": "normalized_999_top_left",
  "source": {
    "captureKind": "full",
    "mapping": "normalized_endpoint_centers/v1",
    "leftPx": 0,
    "topPx": 0,
    "widthPx": 1920,
    "heightPx": 1080
  },
  "environmentFingerprint": "64-lowercase-hex",
  "topologyFingerprint": "64-lowercase-hex",
  "image": {
    "mediaType": "image/png",
    "sha256": "64-lowercase-hex",
    "byteLength": 12345,
    "width": 1920,
    "height": 1080
  }
}
```

The root and each nested object use exactly the displayed keys. `captureKind` is
`full` or `region`; it does not grant unrestricted full-desktop capability. `mapping`
is always the displayed literal. `leftPx` and `topPx` are safe integers in
`-1000000..1000000`; `widthPx` and `heightPx` are integers in `1..32768`.
`capturedAt` is assigned by the CLI after a valid helper response. `expiresAt` is
`capturedAt` plus the configured observation TTL: 300 seconds by default,
configurable per invocation with `observe --ttl` as positive whole seconds or
`unlimited` (`expiresAt` is `null`, meaning the observation never expires by time).
Whole seconds are canonical; sub-second offsets are rejected. The source rectangle
maps observation-local normalized endpoint centers to desktop pixels and is internal
record data, never receipt/history output.

A sidecar is immutable after create-once publication. Its `metadataSha256` means the
SHA-256 of its complete stored UTF-8 sidecar bytes; it is held by referencing records,
not self-embedded in the sidecar.

## Current Live Observation

`live-observation.json` is either a bundle-bound live record or a no-bundle tombstone.
Only a bundle-bound record in `actionable` state can ever authorize coordinates.

A bundle-bound live record has exactly these common root keys:

```text
kind, schemaVersion, runId, workspaceFingerprint, observationId,
publishedByTransactionId, captureMetadataSha256, capturedAt, expiresAt,
coordinateSpace, source, environmentFingerprint, topologyFingerprint, image,
state, stateChangedAt
```

Its `kind` is `cu.live-observation/v1`, `schemaVersion` is `1`, and `source` and
`image` have the exact capture-sidecar shapes. Every duplicated field must equal the
admitted sidecar, and `captureMetadataSha256` must equal its stored byte digest. The
corresponding PNG must still be a confined regular file whose digest, byte length, and
dimensions match both records.

There are two strict bundle-bound state variants:

- `actionable`: the common fields only. `stateChangedAt` equals `capturedAt`.
- `consumed`: common fields plus exactly `consumedByEffectId`. It is written after an
  effect intent is durable and cannot authorize another action.

A no-bundle tombstone has exactly these root keys:

```text
kind, schemaVersion, runId, workspaceFingerprint, observationId,
previousLiveRecordSha256, invalidatedReason, invalidatedAt,
invalidatedByTransactionId
```

Its `kind` is `cu.live-observation-tombstone/v1`, `schemaVersion` is `1`, and
`invalidatedReason` is `expired`, `environment_changed`, or `cleared`.
`previousLiveRecordSha256` binds the live record that was replaced, but a tombstone
never requires its former sidecar or PNG to remain. `invalidatedByTransactionId` is
an archive transaction ID for cleanup cutover or `null` for expiration/environment
invalidation. A tombstone is never action authority.

An actionable record is effectively actionable only while the current CLI time is
strictly before `expiresAt`, the run has no effect journal or archive transaction, and
a fresh environment probe matches its environment and topology fingerprints. On an
expiration or fresh-environment mismatch, `act` replaces it with the corresponding
tombstone under the lock and returns no-effect `blocked`; it never emits input.

A new committed observation atomically replaces the prior live record. The displaced
bundle remains historical and diagnostic-only. History can never promote a sidecar,
a stale live record, transaction staging, or a tombstone back into coordinate authority.

## Archive Transaction and Recovery

`archive-transaction.json` is the one active archive transaction for a run. It is
separate from `effect-journal.json` and covers `publish`, `clear_range`, and
`clear_all` operations. Its exact common root keys are:

```text
kind, schemaVersion, runId, workspaceFingerprint, transactionId, operation,
state, createdAt, updatedAt, priorLive, movedBundles, historyEvents, payload
```

`kind` is `cu.archive-transaction/v1`; `schemaVersion` is `1`; `operation` is one of
`publish`, `clear_range`, or `clear_all`; and `state` is one of `prepared`,
`assets_staged`, or `cutover_committed`.

`priorLive` is `null` or exactly `{ "observationId", "liveRecordSha256" }`.
Each `movedBundles` element has exactly `observationId`, `captureMetadataSha256`,
`imageSha256`, and `imageByteLength`.

`historyEvents` is a distinct ordered array of fixed event descriptors. A capture
descriptor has exactly `eventId`, `at`, `eventType`, `observationId`, and `capturedAt`,
where `eventType` is `capture_retained`, `capture_evicted`, or `capture_cleared`. An
effect-recovery descriptor has exactly `eventId`, `at`, `eventType`, `effectId`, and
`recoveryObservationId`, where `eventType` is `effect_recovered`. The transaction
root supplies the run/workspace/transaction binding for every resulting history line.
The exact descriptors, including `at`, are persisted before cutover and are the only
payloads recovery may append.

The exact `payload` variant is:

- `publish`: `newBundle`, `newLiveRecordSha256`, `replacesObservationId`, and
  `resolvesEffect`; `newBundle` uses the `movedBundles` shape,
  `replacesObservationId` is an observation ID or `null`, and `resolvesEffect` is
  `null` or exactly `{ "effectId", "journalSha256" }`.
- `clear_range`: `invalidatesLive` and `selectedObservationIds`; `invalidatesLive` is
  boolean and `selectedObservationIds` is a distinct ordered list of observation IDs
  matching `movedBundles`.
- `clear_all`: `deletesLiveRecord` and `selectedObservationIds`; `deletesLiveRecord`
  is always `true`, and `selectedObservationIds` is the distinct ordered list of every
  retained bundle, including the current one when present. `historyEvents` is empty
  because clear-all deletes the history archive itself.

`payload` has no extra keys. `updatedAt` is updated at each persisted state change and
is never before `createdAt`.

The transaction sequence is fixed:

1. Publish `prepared` before changing archive visibility or moving an existing bundle.
2. Validate and create-once publish a new bundle for `publish`, then move selected
   historical bundle pairs into that transaction's `trash` directory without deleting
   them. For cleanup operations, move selected pairs into `trash`. Persist
   `assets_staged` only after every listed move is identity-verified.
3. The cutover is singular. For `publish`, atomic replacement of
   `live-observation.json` with an actionable record whose
   `publishedByTransactionId` equals `transactionId` is the cutover. For a
   `clear_range` that selects the live bundle, atomic replacement with a tombstone
   whose `invalidatedByTransactionId` equals `transactionId` is the cutover. For a
   `clear_range` that does not select the live bundle, atomic replacement of the
   transaction to `cutover_committed` is the cutover. For `clear_all`, atomic
   replacement of the transaction to `cutover_committed` is the cutover; no command
   may use the still-present live file while that active transaction exists.
4. After cutover, append the fixed history events where applicable, finalize `trash`
   deletion, and remove the transaction record and private transaction directory.
   `clear_all` forward-finalization removes `live-observation.json`, `history.ndjson`,
   all retained bundle files, and private archive state; `run.json` and the lock
   namespace remain so a later fresh `observe` can rebuild an archive.

Before cutover, recovery rolls back: it restores moved bundles, discards the unpublished
new bundle, and removes the transaction. After cutover, recovery only finalizes forward:
it preserves a publish record or cleanup tombstone, appends any missing fixed history
events, deletes transaction trash, and removes the transaction. For `clear_all`, it
removes the live/history/archive records during forward finalization rather than
preserving a tombstone.

Positive post-cutover evidence is exactly one of: a bundle-bound live record whose
`publishedByTransactionId` equals the active transaction for `publish`; a tombstone
whose `invalidatedByTransactionId` equals it for live-selected `clear_range`; or
`state: "cutover_committed"` for non-live `clear_range` and `clear_all`. These signals
remain positive even when a crash left an earlier transaction state on disk. Any other
state/live combination, an unprovable listed bundle or snapshot, an event descriptor
that cannot be identified uniquely, or changed cleanup identity stops with
`archive_recovery_required`. While that condition exists, `observe`, `act`, `history`,
`clear`, and `clearall` are blocked; no automatic deletion or replay is permitted.
Read-only `status` may report the blocked condition without repairing it.

A normal mutating command detects and resolves a provable interrupted archive transaction
under the run lock before interpreting live/archive state. A successful transaction never
exposes a staging or trash bundle as an observation receipt or action authority.

## Retention, Quota, and History

A run retains at most 128 historical bundles in addition to at most one current live
bundle. The 536,870,912-byte (512 MiB) archive budget is the exact sum of PNG and
sidecar byte lengths for all committed retained bundles, including the live bundle.
It excludes private staging/trash and bounded control records; those are transient but
never action authority.

Before publishing a new live bundle, `cu` determines whether the post-cutover archive
will fit both limits. It selects oldest historical bundles first, ordered by
`capturedAt` ascending then `observationId` ASCII ascending. It never selects the
current actionable bundle, a consumed live bundle referenced by an unresolved effect
journal, or a transaction-private bundle. If enough eligible history cannot be
selected, `observe` fails with `capture_quota_exceeded`, leaves the former live record
untouched, and publishes no receipt for the new capture.

Eviction is not silent: every finalized removal has a durable history event and an
observe/checkpoint receipt reports its `evictedHistoryCount`. A temporary staged
bundle may exist during a transaction, but a completed transaction always meets both
steady-state quota limits.

`history.ndjson` is a bounded diagnostic event log, never action authority. Each line
is at most 8,192 UTF-8 bytes and is one strict `cu.history.event/v1` object with common
exact fields `kind`, `schemaVersion`, `eventId`, `transactionId`, `at`, `eventType`,
`runId`, and `workspaceFingerprint`. It copies exactly one persisted transaction event
descriptor; capture events additionally have `observationId` and `capturedAt`, while
`effect_recovered` events instead have `effectId` and `recoveryObservationId`.
Finalization scans for each descriptor's event ID and appends only an absent identical
line, making crash recovery idempotent. A malformed, duplicate, or non-identical event
ID is archive corruption, not a reason to infer an outcome.

The log is limited to 4 MiB and 4,096 lines. Under the run lock and with no archive
transaction, it may be atomically compacted into canonical retained-capture events and
the newest 512 terminal unavailable events. Compaction never invents a retained bundle
or hides an unresolved effect. For every syntactically valid non-current observation ID
whose retained sidecar/PNG pair is absent, including an ID whose tombstone was compacted
away or one never retained by this run, `history show` returns the same safe
`availability: "unavailable"` receipt. It never reveals which case applied or treats
an absent item as valid evidence.

## Effect Journal and No-Replay Recovery

`effect-journal.json` exists only from durable intent until a safely proven terminal
flow or a fresh-observation recovery. It has exactly these common root keys:

```text
kind, schemaVersion, runId, workspaceFingerprint, effectId, createdAt,
state, stateChangedAt, observation, plan
```

`kind` is `cu.effect-journal/v1`; `schemaVersion` is `1`; and `state` is `intent`,
`partial`, or `indeterminate`. `intent` has only the common keys. `partial` and
`indeterminate` add exactly `reason`, one of `helper_lost`, `input_unproven`,
`cleanup_unproven`, `checkpoint_capture_failed`, or `checkpoint_publish_failed`.

`observation` has exactly `observationId`, `liveRecordSha256`,
`captureMetadataSha256`, `imageSha256`, `environmentFingerprint`, and
`topologyFingerprint`. These bind the intent to the consumed live evidence.

`plan` has exactly `redactedDigest`, `leafActionCount`, `coordinateActionCount`,
`declaredDelayMs`, `typeText`, and `terminalDecision`. `leafActionCount` is an integer
in `1..32`; `coordinateActionCount` is an integer in `0..32`; and `declaredDelayMs` is
an integer in `0..30000`. `redactedDigest` is SHA-256 of the canonical normalized
segment after each `type_text` action is replaced with exactly
`{ "kind": "type_text", "scalarCount": n, "utf8Bytes": n }`. It is not a hash of
raw text. `typeText` has exactly integer `actionCount` in `0..32`, `scalarCount` in
`0..65536`, and `utf8Bytes` in `0..65536`. These permitted aggregate length totals
are accounting only, never a content-derived fingerprint. `terminalDecision` is
`completed` or `checkpoint`. No journal, event, receipt, or error serializes raw typed
text or a digest derived from it.

`act` writes an `intent` journal only after every no-effect admission check succeeds
and before its first native-input emission. It then atomically marks the referenced
live observation `consumed` with `consumedByEffectId`. A crash after either write is
unresolved and forbids automatic replay. A fully proven completed flow removes the
journal only after cleanup and its terminal archive work are durable. A checkpoint flow
removes it only after the replacement live observation has committed.

Every persisted `intent`, `partial`, or `indeterminate` journal is unresolved after its
own command process ends and blocks `act`, `clear`, and `clearall`. A normal `observe`
is permitted specifically to recover: it captures and validates fresh evidence without
replaying any action, carries the journal binding in its archive transaction, and only
after new-live cutover appends an `effect_recovered` event and removes the old journal.
This records a new safe visual/input boundary but makes no claim that the prior effect
achieved an application outcome. If that recovery cannot complete, the journal remains
and destructive cleanup stays blocked.

## Stable Failure Classification

The following machine codes are reserved by this contract:

| Code | Meaning | Default exit class |
| --- | --- | --- |
| `capture_invalid` | Helper capture or bundle validation failed before publication. | blocked (3) |
| `capture_quota_exceeded` | The new capture cannot fit without evicting protected evidence. | blocked (3) |
| `observation_invalid` | Live/sidecar/image binding is malformed, mismatched, or untrusted. | internal/corrupt (1) |
| `observation_unavailable` | No current actionable live observation exists. | blocked (3) |
| `observation_expired` | Current evidence exceeded its configured lifetime (default 300 seconds; `unlimited` never expires). Retrying with a fresh observation is the intended recovery. | blocked (3) |
| `observation_consumed` | The current observation was consumed by a prior effect and cannot authorize another action; capture a new observation before cleanup. | blocked (3) |
| `observation_environment_changed` | Fresh environment/topology does not match live evidence. | blocked (3) |
| `archive_recovery_required` | Archive transaction state cannot be proved for rollback or finalization. | blocked (3) |
| `effect_journal_invalid` | Effect journal is malformed or inconsistent with its live binding. | internal/corrupt (1) |
| `effect_journal_unresolved` | A durable intent/partial/indeterminate effect blocks the requested operation. | blocked (3) |

`history show` for any unavailable capture is a successful safe receipt with
`availability: "unavailable"`, not an attempt to revalidate or restore that capture.
